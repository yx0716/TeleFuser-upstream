# 远程查看 LingBot-World-Fast 流式输出（SSH 隧道 + TURN 中继）

本文记录：当 **stream server 跑在远端 GPU 机器、而你的笔记本只能通过 SSH 到达这台机器**时，
如何在本地浏览器看到 WebRTC 流式输出。这套方法的名字叫
**「SSH 本地端口转发（`ssh -L`）+ TURN-over-TCP 媒体中继」**。

---

## 1. 为什么不能直连

WebRTC 由两条通道组成，走两种协议：


| 通道            | 协议                 | 内容                         |
| ------------- | ------------------ | -------------------------- |
| 信令（signaling） | HTTP / TCP         | 交换 SDP offer/answer、ICE 候选 |
| 媒体（media）     | **UDP / RTP**（ICE） | 真正的视频帧                     |


问题出在媒体是 **UDP**：

- 笔记本到这台机器**只有 SSH 端口可达**（经网关；其它端口如 8091/8099 直连会被拒——实测 Safari 报「无法连接服务器」）。
- `ssh -L` 本地端口转发**只转发 TCP**，转不了 WebRTC 的 UDP 媒体。

所以：单纯 `ssh -L` 能把网页和信令转通，但视频会黑屏。解决办法是让**媒体也走 TCP**——这就是 TURN 的作用。

---

## 2. 方法拓扑

```
   [ 笔记本 ]                              [ 远端 GPU 机器 ]
                                           （都在 localhost / 同一台）
 浏览器 localhost:8091 ──┐
                         │  ssh -L 8091     ┌─ demo HTTP (8091)
                         ├─────────────────►│   └─(--proxy-backend)→ stream server (8099)
                         │  (TCP 隧道)       │       └─ aiortc 生成视频，offer host 候选
 浏览器 TURN              │                  │
 localhost:3478 ─────────┤  ssh -L 3478     ├─ coturn (3478, TCP 监听)
                         └─────────────────►│   └─ relay-ip 127.0.0.1
                            (TCP 隧道)       │      ↕ 与 aiortc 同机，互相直达
                                            └─ 媒体：浏览器 ⇄ coturn(TCP) ⇄ aiortc
```

要点：

- `**--proxy-backend`（demo 默认开）**：浏览器只跟 demo 源（8091）说话，demo 在**服务端**把
`/v1/stream/webrtc/*` 信令代理转发到 stream server（8099）。所以**信令口 8099 不用转发**，
浏览器只需要 8091。
- **媒体走 TURN**：浏览器用 `turn:localhost:3478?transport=tcp` 经 SSH 隧道连到远端 coturn，
媒体以 **TCP** 在浏览器和 aiortc 之间中继。coturn 与 aiortc 同机（`relay-ip=127.0.0.1`），互相直达。
- `**--force-turn-relay`**：强制浏览器只用 relay 候选，不浪费时间尝试根本不可达的 host 候选（远端内网 IP）。

最终只需转发 **2 个 TCP 端口：8091 + 3478**。

## 3. 远端三件套（在 GPU 机器上跑）

> 连接：办公网 `ssh teleai-h100`；非办公网 `ssh teleai-h100-home`（内网 IP 10.127.48.3）。
> 仓库：`/pvcteam/jinyx5/repo/telefuser-internal-main`，虚拟环境 `.venv`，模型 `/pvcplatform/model_zoo`。

```bash
cd /pvcteam/jinyx5/repo/telefuser-internal-main

# (1) stream server —— 必须用修复版 config（text/vae 都在 cuda，warmup 才快，见 README）
TF_MODEL_ZOO_PATH=/pvcplatform/model_zoo \
  .venv/bin/telefuser stream-serve examples/lingbot/stream_lingbot_world_fast.py \
  -p 8099 --host 0.0.0.0 --skip-validation
# 等日志出现 “Starting stream server on 0.0.0.0:8099”（模型加载 ~70s）

# (2) coturn —— TURN 中继（本机已预装 /usr/bin/turnserver）
turnserver -n --no-tls --no-dtls \
  --listening-port=3478 --relay-ip=127.0.0.1 \
  --lt-cred-mech --user=telefuser:telefuser123 --realm=telefuser \
  --min-port=49152 --max-port=49200

# (3) demo —— 指向本机 stream server，开 TURN + 强制 relay；图和 poses 用 example 00
TF_MODEL_ZOO_PATH=/pvcplatform/model_zoo \
  .venv/bin/python examples/stream_server/webrtc_bidirectional_demo.py \
  --server-url http://localhost:8099 \
  --image-path /pvcplatform/model_zoo/lingbot-world-fast/assets/teaser.png \
  --turn-url "turn:localhost:3478?transport=tcp" \
  --turn-username telefuser --turn-credential telefuser123 \
  --force-turn-relay --no-open
# 想要 example 00 的奇幻丛林：--image-path .../00/image.jpg --action-path .../00
```

三个进程都用 `nohup ... &` 后台跑、日志落到 `runs/` 即可。

## 4. 本地操作

```bash
# (1) 开 SSH 隧道，转发 8091（页面）+ 3478（TURN），保持这个终端不关
ssh -L 8091:localhost:8091 -L 3478:localhost:3478 teleai-h100      # 办公网
# 非办公网把别名换成 teleai-h100-home

# (2) 浏览器打开（注意是 localhost，不是远端 IP）
#     http://localhost:8091
# (3) 输入 prompt → Connect → 方向键 / D-pad 控制镜头
```

## 5. ⚠️ 现在做不到实时（重要）

实测：单张 H100 上生成速率约 **4.2 fps**（每 chunk ~2.76s，约 11.6 输出帧），而播放目标
**16 fps**——**生成比播放慢约 3.8×**。所以画面会缓冲、滞后，**不是流畅实时**。
demo 先推一张 preview 占位帧、再「追」真帧，就是在掩盖这个差距。

要逼近实时，可往这些方向优化（都会牺牲质量或吃更多资源）：

- **更少去噪步数**（蒸馏 / few-step 采样器）——最直接。
- **多卡序列并行（Ulysses SP）**：DiT 分到多张卡，单 chunk 更快。
- **FP8 / INT8 量化** DiT，提高吞吐。
- **降分辨率 / 降 chunk 帧数**：减少每 chunk 计算量。

先用**离线脚本**量化「改了配置后单 chunk 多快」，再决定 streaming 参数（见 `offline_lingbot_world_fast.py`）。

## 6. 分辨率

当前生成分辨率 **832×480**（latent 21×60×104）。由 `PPL_CONFIG["max_area"] = 480*832`
决定：`_best_output_size` 按输入图宽高比，把这个面积分配成 16×16 对齐的宽高。改清晰度就调
`max_area`（显存 / 单 chunk 耗时相应上升，进一步拉低帧率）。

## 7. 常见坑

- **浏览器直连远端 IP 打不开**：笔记本只有 SSH 口可达，必须走隧道 + `localhost`。
- **视频黑屏 / ICE failed**：媒体没走通。检查 coturn 在跑、3478 已转发、demo 带了
`--turn-url` + `--force-turn-relay`、TURN 用户名/密码一致。看 `runs/.../turn.log` 有没有 allocation。
- **warmup 卡 ~100s、GPU 0%**：stream config 把 text/vae 放了 cpu。改成 cuda（见 README「Known blocker」）。
- `**--image-path` 失效**：必须是**完整文件路径**且作为**单个参数**；传成目录或被换行拆断会静默退化成「无图」。
